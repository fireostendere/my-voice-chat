# LiveKit Meet

**Документация:** [English](./README.md) | Русский

Веб-приложение для видеоконференций на Next.js и LiveKit. Это доработанный форк
[LiveKit Meet](https://github.com/livekit/meet) с синхронным кинотеатром,
push-to-talk, E2EE, записью комнат и настройками медиа.

![Скриншот LiveKit Meet](./.github/assets/livekit-meet.jpg)

## Что нужно для запуска

- **Node.js 18 или новее**. В CI используется Node 24.
- Доступ к **LiveKit Cloud** или собственному LiveKit Server.
- Три значения от LiveKit: `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` и
  `LIVEKIT_URL`.
- Браузер с доступом к камере и микрофону. Для YouTube, VK Video и глобального push-to-talk
  рекомендуется Chrome или Edge.

Без LiveKit credentials главная страница запустится, но вкладка **Demo** не сможет
выдать токен и подключить участника к комнате.

## Быстрый запуск

### 1. Установите зависимости

Из корня репозитория выполните:

```bash
corepack pnpm install
```

В `package.json` зафиксирован `pnpm@10.18.2`, поэтому Corepack сам использует нужную
версию. Если команда `pnpm` уже доступна, можно выполнить обычный `pnpm install`.

### 2. Создайте `.env.local`

macOS, Linux или WSL:

```bash
cp .env.example .env.local
```

Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Файл `.env.local` уже исключён из Git. Не коммитьте API secret.

### 3. Добавьте LiveKit credentials

Создайте проект в [LiveKit Cloud](https://cloud.livekit.io/) и возьмите URL, API key
и API secret из настроек проекта. Для собственного LiveKit Server используйте его
URL и настроенные на сервере ключи.

Заполните `.env.local`:

```dotenv
LIVEKIT_API_KEY=ваш-api-key
LIVEKIT_API_SECRET=ваш-api-secret
LIVEKIT_URL=wss://ваш-проект.livekit.cloud
```

Важно:

- `LIVEKIT_URL` должен быть WebSocket-адресом с `wss://` или `ws://`, а не адресом
  панели управления с `https://`.
- `LIVEKIT_API_SECRET` используется только серверной частью Next.js. Никогда не
  добавляйте к нему префикс `NEXT_PUBLIC_`.
- После изменения `.env.local` перезапустите dev-сервер.

### 4. Запустите приложение

```bash
corepack pnpm dev
```

Откройте [http://localhost:3000](http://localhost:3000).

### 5. Проверьте комнату

1. Откройте вкладку **Demo**.
2. Нажмите **Start Meeting**.
3. Введите имя, выберите камеру и микрофон, затем подключитесь.
4. Скопируйте адрес созданной комнаты и откройте его в режиме инкогнито или другом
   профиле браузера, чтобы проверить второго участника.
5. Разрешите браузеру доступ к камере и микрофону.

После этого приложение готово к локальной разработке.

## Режимы подключения

### Demo

Приложение само запрашивает JWT через `/api/connection-details`. Для этого режима
обязательны три серверные переменные LiveKit из `.env.local`.

### Custom

На вкладке **Custom** пользователь вручную вводит `wss://` URL сервера и готовый
participant token. Этот режим не запрашивает токен через локальный API, но токен всё
равно должен быть заранее создан доверенным сервером.

## Переменные окружения

### Обязательные

| Переменная           | Назначение                                                     |
| -------------------- | -------------------------------------------------------------- |
| `LIVEKIT_API_KEY`    | Серверный API key для выпуска participant token.               |
| `LIVEKIT_API_SECRET` | Серверный API secret. Не передаётся в браузер.                 |
| `LIVEKIT_URL`        | WebSocket URL LiveKit, например `wss://project.livekit.cloud`. |

### Опциональные

| Переменная                            | Назначение                                                                |
| ------------------------------------- | ------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SHOW_SETTINGS_MENU=true` | Показать настройки устройств, фона, Krisp и записи.                       |
| `NEXT_PUBLIC_LK_RECORD_ENDPOINT`      | Endpoint записи, обычно `/api/record`.                                    |
| `NEXT_PUBLIC_CONN_DETAILS_ENDPOINT`   | Другой endpoint выдачи токена. По умолчанию локальный API.                |
| `NEXT_PUBLIC_COMPANION_WS_URL`        | WebSocket companion для передачи комнаты, PTT и обычных BitTorrent-пиров. |
| `NEXT_PUBLIC_PTT_WS_URL`              | WebSocket локального PTT helper. По умолчанию `ws://127.0.0.1:7331`.      |
| `NEXT_PUBLIC_DATADOG_CLIENT_TOKEN`    | Client token Datadog. Нужен вместе с `NEXT_PUBLIC_DATADOG_SITE`.          |
| `NEXT_PUBLIC_DATADOG_SITE`            | Site Datadog.                                                             |

Настройки загрузки и сборки companion задаются в разных окружениях:

| Переменная              | Где задаётся                               | Назначение                                                                    |
| ----------------------- | ------------------------------------------ | ----------------------------------------------------------------------------- |
| `COMPANION_EXE_URL`     | Next.js server environment / `.env.local`  | HTTPS-зеркало `LiveKitCompanionSetup.exe` вместо стандартного GitHub Release. |
| `COMPANION_WEB_APP_URL` | GitHub repository variable или desktop env | Управляемый HTTPS-адрес, который открывает Windows Companion.                 |

`COMPANION_WEB_APP_URL` не является переменной Next.js и не передаётся desktop-клиенту
из `.env.local`. Изменение repository variable применяется при следующей сборке
установщика; одноимённая переменная процесса переопределяет упакованный адрес.

Для записи также нужны `S3_KEY_ID`, `S3_KEY_SECRET`, `S3_ENDPOINT`, `S3_BUCKET` и
`S3_REGION`. Публичные переменные `NEXT_PUBLIC_*` встраиваются во время сборки,
поэтому задавайте их до `pnpm build`.

## Кинотеатр

После входа в комнату нажмите **Кинотеатр** в левом верхнем углу.

- **Ссылка, YouTube или VK:** вставьте прямую ссылку на MP4/WebM/Ogg, HLS playlist
  (`.m3u8`), YouTube либо обычную ссылку VK Video с `vk.ru`, `vk.com` или
  `vkvideo.ru`. Поддерживаются видео, клипы, ссылки из ленты с `?z=video…` и
  экспортные `video_ext.php` с ключом доступа. Воспроизведение, пауза и позиция
  синхронизируются через LiveKit data channel.
- **Локальный файл:** файл остаётся на компьютере ведущего. Браузер захватывает его
  как media stream и публикует через LiveKit как screen share.
- **Торрент:** вставьте magnet-ссылку или выберите `.torrent`. Кинотеатр сначала
  использует локальный companion с обычными BitTorrent-пирами. Если companion не
  установлен или не запущен, автоматически включается браузерный WebTorrent.

Исходная VK-ссылка не передаётся в iframe напрямую: приложение проверяет точный домен,
извлекает идентификаторы владельца/видео и заново строит официальный `video_ext.php`.

Команды воспроизведения, полноэкранный режим, picture-in-picture и остановка доступны
только участнику, который запустил связанное видео. У зрителей элементы управления
обычного `<video>` скрыты, YouTube запрашивается с `controls=0`, а все media-элементы и
iframe не принимают мышь или клавиатуру. Chrome кросс-доменного VK-плеера нельзя надёжно
скрыть, поэтому он может остаться видимым, но защитный слой делает его неактивным, а
синхронные команды всё равно принимаются только от ведущего. Исключение — отдельная
кнопка запуска звука, которую браузер может потребовать из-за запрета autoplay.

Торрент скачивает только ведущий. Зрители не подключаются к раздаче, а получают один
готовый видеопоток через LiveKit. Next.js-сервер не загружает и не хранит torrent-файл
или видео. Browser fallback видит только WebRTC-совместимых WebTorrent-пиров и web
seeds, поэтому для обычных публичных magnet-ссылок рекомендуется запустить companion.

Прямой источник должен воспроизводиться браузером, а HLS-сервер — разрешать CORS для
playlist и сегментов. YouTube и VK Video в этом приложении надёжнее работают в
Chromium-браузерах из-за ограничений COEP и credentialless iframe. Ведущий должен иметь
право смотреть выбранное VK-видео; закрытое видео без экспортного ключа VK не разрешит
встроить.

## Локальный companion

Веб-страница не видит нажатия клавиш, когда фокус находится в игре или другом
приложении. Companion добавляет глобальную кнопку разговора и поддержку обычных
BitTorrent-пиров для кинотеатра:

На главной странице или в постоянно видимой верхней панели комнаты нажмите **Download
companion** и запустите полученный `LiveKitCompanionSetup.exe`. Установщик:

- уже содержит Node.js и все зависимости, поэтому заранее устанавливать их не нужно;
- при необходимости ставит официальный Microsoft Edge WebView2 Runtime для веб-клиента;
- ставит приложение без прав администратора в `%LOCALAPPDATA%\Programs\LiveKitCompanion`;
- создаёт ярлыки, добавляет опциональный автозапуск и запускает companion в фоне;
- добавляет обычное удаление приложения через настройки Windows.

Установленный клиент сообщает сайту свою версию. Если версия Companion в текущей версии
сайта новее, внутри приложения появляется уведомление со ссылкой на новый установщик.

Ярлык **LiveKit Companion** запускает фоновый сервис и открывает полноценный веб-клиент
голосового чата в собственном окне WebView2 с иконкой LiveKit в панели задач. Нативная
панель содержит **Home / Chat**, **Settings**, **Back** и **Reload**. В Settings можно
выбрать активную комнату, передать magnet-ссылку или файл `.torrent`, управлять
воспроизведением и поменять глобальную PTT-клавишу. Переходы за пределы настроенного
origin открываются в системном браузере. Иконка LiveKit в трее повторно открывает клиент
или завершает сервис. Удалить приложение можно через **Uninstall LiveKit Companion**
или **Windows Settings → Apps → Installed apps**.

Встроенный клиент разрешает навигацию только по настроенному origin и локальной странице
Settings. Камера, микрофон и захват экрана разрешаются только веб-приложению; остальные
ссылки уходят в системный браузер. Маркер `window.__LIVEKIT_COMPANION__` сообщает сайту,
что он открыт в WebView2, и передаёт установленную версию для проверки обновлений, не
раскрывая данные доступа к локальным Settings.

Когда обычный браузер переходит на `/rooms/<roomName>` или `/custom`, именно страница
этого маршрута не монтирует LiveKit-клиент до проверки Companion; главная страница
только выполняет переход. Код в браузере обращается исключительно к loopback WebSocket и
требует протокол v3 с возможностью `open-room`. Запущенный упакованный Companion проверяет
точный same-origin URL комнаты и открывает либо переиспользует своё единственное окно.
Path, query-параметры и E2EE hash сохраняются.

Пока команда не отправлена, отсутствующий, остановленный, старый или несовместимый
Companion не мешает комнате открыться в браузере. После отправки `open-room` текущая
вкладка работает fail-closed: принятие, явный отказ, потерянный ответ или тайм-аут в любом
случае оставляют её пассивной и не монтируют LiveKit-комнату. Поэтому второй участник и
второй источник звука не появятся, даже если результат нативного открытия неизвестен.
Кнопки продолжения нет, и старая вкладка никогда не возобновляет работу автоматически.
Чтобы открыть комнату в браузере, выберите **Exit** у иконки Companion в трее (или иначе
остановите фоновый сервис), затем перезагрузите ссылку либо откройте её в новой вкладке.
Просто закрыть нативное окно крестиком недостаточно: работающий в фоне сервис снова его
откроет при следующей передаче.

Удалённый Next.js-сервер не может проверить `127.0.0.1` конкретного пользователя, поэтому
проверку выполняет загруженная страница. Автозапуск фонового сервиса включается
установщиком по умолчанию: это позволяет без browser prompt открыть закрытое нативное
окно, когда сервис уже работает. Полный URL разрешён только для точных same-origin
`/rooms/<one-segment>` или `/custom`. Он может содержать JWT и E2EE hash, поэтому не
записывается в аргументы процесса, файл или лог. Node передаёт ограниченный JSON
единственному WebView2-окну через Windows named pipe текущего пользователя, а нативная
сторона повторно проверяет URL, маршрут и origin.

При первом входе встроенный WebView2-клиент или обычный Chrome/Edge может сначала
запросить доступ сайта к локальной сети: разрешите его, чтобы страница увидела
приложение на этом ПК. Затем companion покажет собственный Windows-диалог. Проверьте
origin сайта и нажмите **Да**. Выбранный адрес основного веб-клиента доверяется
автоматически; диалог нужен для других новых origins. Разрешение сохраняется локально и
включает для origin и рацию, и торрент-кинотеатр.
При ручной установке для разработки адрес можно выбрать через **Settings → Voice-chat
server → Connect in app**. Release-сборка получает управляемый адрес из repository
variable `COMPANION_WEB_APP_URL` (по умолчанию `https://api.iroslyakov.com/`); одноимённая
переменная окружения переопределяет его при запуске managed-установки. Это именно адрес
веб-приложения; LiveKit WebSocket URL и секреты в Companion вводить не нужно.
Удалённый адрес обязан использовать HTTPS; HTTP разрешён только для loopback-разработки.
Если адрес не задан или страница не загрузилась, приложение открывает локальные Settings.

По умолчанию рация использует `F8`. Нажмите на большую кнопку бинда, затем нажмите
нужную клавишу или боковую кнопку мыши — новый Talk Key применится сразу, без отдельной
кнопки сохранения и без перезапуска. `Esc` отменяет захват.

Адрес `127.0.0.1:7331` означает этот же компьютер пользователя, а не удалённый сервер.
Его не нужно заменять адресом Next.js/LiveKit: страница, открытая с HTTPS-сервера,
подключается к companion локально из браузера.

Вместо стороннего универсального keyboard hook установщик содержит собранный из этого
репозитория `LiveKitCompanionNative.exe`. Он проверяет состояние только выбранной
PTT-клавиши, не перебирает остальные клавиши и не получает вводимый текст. Файлы пока
не подписаны цифровым сертификатом, поэтому SmartScreen или сторонний антивирус всё
равно могут показать предупреждение о репутации.

Ручная установка для разработки остаётся доступна:

```powershell
cd companion
npm install
npm run build:ptt-helper
npm run keys
$env:PTT_KEY="F8"; npm start
```

После подключения companion микрофон работает в режиме рации: удержание выбранной
клавиши включает микрофон, отпускание выключает. Торрент-вкладка автоматически
обнаруживает тот же процесс. Подробности находятся в
[`companion/README.md`](./companion/README.md).

Companion подключается к обычным BitTorrent-пирам по TCP/UDP, поэтому раздающим не
нужна поддержка WebRTC. Практические ограничения остаются: в раздаче должны быть
доступные пиры, она должна содержать видео, а браузер на компьютере ведущего должен
уметь декодировать контейнер и кодеки этого видео.

Для управляемой ручной установки можно заранее указать точный origin и отключить
интерактивный запрос:

```powershell
$env:COMPANION_ORIGINS="https://ваш-чат.example.com"; npm start
```

Без этой настройки companion один раз покажет Windows-диалог для подтверждения origin.

Чтобы отключить только рацию, но оставить torrent companion, добавьте в `.env.local`:

```dotenv
NEXT_PUBLIC_PTT_WS_URL=
NEXT_PUBLIC_COMPANION_WS_URL=ws://127.0.0.1:7331
```

## Запись комнаты

Запись использует LiveKit Egress и S3. Минимально нужно добавить S3-переменные и:

```dotenv
NEXT_PUBLIC_SHOW_SETTINGS_MENU=true
NEXT_PUBLIC_LK_RECORD_ENDPOINT=/api/record
```

Затем используйте **Settings -> Recording** в комнате. E2EE-комнаты записывать
нельзя: серверный Egress не может расшифровать их медиапотоки.

Маршруты `/api/record/*` и `/api/connection-details` не имеют авторизации. Это
демонстрационная конфигурация; перед публичным развёртыванием обязательно добавьте
аутентификацию и проверку прав.

## Production-запуск

```bash
corepack pnpm build
corepack pnpm start
```

По умолчанию приложение откроется на `http://localhost:3000`. На сервере или в
Vercel задайте те же переменные окружения в настройках окружения, а не только в
локальном `.env.local`.

## Частые проблемы

### `pnpm: command not found`

Используйте команды через Corepack: `corepack pnpm install`, `corepack pnpm dev` и
так далее. Если не найден и `corepack`, установите актуальную LTS-версию Node.js.

### `LIVEKIT_URL is not defined`

Не создан `.env.local`, переменная осталась пустой или dev-сервер не был перезапущен
после изменения файла.

### Комната открылась, но подключение не происходит

Проверьте, что URL начинается с `wss://`, API key и secret относятся к тому же
LiveKit-проекту, а браузер или firewall не блокирует WebSocket/WebRTC.

### Нет камеры или микрофона

Разрешите доступ для `localhost` в браузере и убедитесь, что устройство не занято
другим приложением. Камера и микрофон требуют secure context; `localhost` считается
безопасным для локальной разработки.

### Видео по ссылке не запускается

Проверьте формат и доступность URL непосредственно в браузере. Для HLS источник должен
разрешать загрузку playlist и сегментов с origin приложения. Для VK поддерживаются
обычные `video…`/`clip…` ссылки с `vk.ru`, `vk.com`, `vkvideo.ru`, ссылки с `?z=` и
экспортные `video_ext.php`. Закрытое видео может потребовать экспортный ключ доступа, а
запрещённое владельцем встраивание обойти нельзя.
